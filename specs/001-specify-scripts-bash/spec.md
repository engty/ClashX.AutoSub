# Feature Specification: YAML订阅配置增强

**Feature Branch**: `[001-specify-scripts-bash]`  
**Created**: 2025-10-18  
**Status**: Draft  
**Input**: User description: "/speckit.specify ...改进订阅链接替换与结构化 YAML 编辑体验"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 持续化订阅链接替换 (Priority: P1)

当订阅站点发放新的短效链接时，用户希望系统仅替换 YAML 模板中的链接字段并保持其它自定义内容不变，以便沿用既有测速、自动优选配置。

**Why this priority**: 链路失效会导致节点完全不可用，是整个增强项目的基础能力。

**Independent Test**: 构造含自定义策略的 `template.yaml`，触发一次新的订阅导入，验证仅链接字段更新且其它字段未变。

**Acceptance Scenarios**:

1. **Given** 模板中已存在自定义策略，**When** 用户提供新订阅链接，**Then** 系统替换模板中的 `proxy-providers` 源地址且其它字段保持不变。  
2. **Given** 模板中存在多订阅源，**When** 用户选择部分源更新，**Then** 只有被选源的链接被替换。  

---

### User Story 2 - 可视化结构编辑器 (Priority: P1)

非技术用户希望通过图形界面（选择器、表单、增删按钮）管理 YAML 模块，无需直接编辑文本即可完成节点分组、策略与规则修改。

**Why this priority**: 直接文本编辑门槛高，若无图形编辑器则项目核心卖点无法触达目标用户。

**Independent Test**: 通过 UI 操作新增一个策略组并保存，比较输出 YAML 与预期结构一致；通过订阅管理界面的“模板编辑”页签访问并验证导航与权限行为。

**Acceptance Scenarios**:

1. **Given** 用户打开“节点源”模块配置，**When** 添加新订阅源并填写链接、更新策略，**Then** 预览 YAML 中出现对应结构。  
2. **Given** 用户在“自定义配置”文本框中输入额外 YAML，**When** 保存触发 dry-run 校验，**Then** 若格式有效则写入模板，否则提示错误并忽略该配置。  
3. **Given** 用户在“策略组”界面选择删除某节点，**When** 点击保存，**Then** YAML 输出中移除该节点且相关规则同步更新。  

---

### User Story 3 - 多订阅融合与最优节点选择配置 (Priority: P2)

运维用户希望在界面中管理多订阅融合策略，对同地区节点执行延迟测试并自动选择表现最佳的节点集合。

**Why this priority**: 该功能体现项目与 Clash.Meta 原版的差异化能力，但依赖前两项基础能力。

**Independent Test**: 为两个地区配置不同订阅源，运行测试流程，确认 YAML 中生成带有 `url-test`/`select` 策略且标记最优节点。

**Acceptance Scenarios**:

1. **Given** 用户为地区“Japan”配置多个订阅源，**When** 触发延迟测试，**Then** 系统在 YAML 中更新 `proxy-groups` 里“Japan 智选”列表并按性能排序。  
2. **Given** 某订阅源测试失败，**When** 完成融合过程，**Then** YAML 中保留失败记录并自动回退至最近一次成功节点列表。  

---

### User Story 4 - 模板导入导出与安全复用 (Priority: P1)

运维或高级用户希望可以在多台设备间安全迁移模板，导出时自动加密，导入时校验口令并在失败时保持现有配置不被污染。

**Why this priority**: 模板调整常需跨设备协作，若缺乏安全的导入导出流程将使快照复用不可行。

**Independent Test**: 通过 UI 导出模板得到加密文件；使用正确口令导入恢复成功，自定义 YAML 与快照同步；使用错误口令导入时保留原模板并提示失败记录。

**Acceptance Scenarios**:

1. **Given** 用户选择导出模板并设置口令，**When** 操作完成，**Then** 生成的文件仅在输入该口令后才能被导入。  
2. **Given** 用户导入外部模板，**When** 输入正确口令并通过 dry-run 验证，**Then** 模板与快照更新且审计日志新增成功记录。  
3. **Given** 用户导入时口令错误或 dry-run 失败，**When** 操作结束，**Then** 原模板保持不变并提示错误详情，同时写入日志供追溯。  

---

### Edge Cases

- 当订阅站点返回空或错误链接时，系统需要回滚到上一次成功的链接并提示用户。  
- YAML 模板缺失必填模块（如 `proxy-groups`）时，编辑器应阻止保存并给出指引。  
- 当用户同时编辑模板并更新订阅链接时，系统需序列化操作或提示变更冲突，避免覆盖其它改动。  
- 多订阅源融合过程中若测试超时，应允许用户配置重试次数与超时时长。  
- 导出模板时若口令加密失败或无法写盘，系统必须中止操作并保留审计日志提示。  

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须支持对模板中每个订阅源链接进行单独检测与替换，并保持其它配置不变。  
- **FR-002**: 前端必须提供结构化编辑界面，覆盖订阅源、节点、策略、规则、脚本等核心模块，并在订阅管理页新增“模板编辑”页签承载该界面。  
- **FR-003**: 编辑器必须提供实时 YAML 预览与差异提示，防止保存无效结果，并支持自定义 YAML 文本框输入与自动格式化校验；当格式化后仍无法通过验证时，必须丢弃该自定义配置并在 UI 提示“自定义配置未加载”。过滤规则模块需同时提供关键字/标签可视化助手与正则文本编辑，两种模式保持字段同步。  
- **FR-004**: 系统必须触发延迟测试并根据结果更新“智选”策略组，同时保留原始排序供回滚。  
- **FR-005**: 保存操作必须通过 Tauri 命令进行持久化，并在失败时回滚到保存前快照，且若检测到外部 YAML 已变更则阻止保存并提示重新加载。  
- **FR-006**: 用户可导入导出模板快照，导出文件须通过口令或现有加密模块保护，导入时需验证口令与 dry-run；若校验失败则放弃写盘并记录错误。  
- **FR-007**: 系统必须在 UI 中标注订阅链接剩余有效时间：剩余 ≤ 5 分钟时以黄色提醒，≤ 60 秒时标红并阻止保存，提示用户刷新链接。  
- **FR-008**: 编辑器必须提供权限校验，防止非预期模块（如内置安全策略）被误删；受保护字段需在 UI 显示只读状态，删除操作必须二次确认方可执行。  
- **FR-009**: 系统必须记录所有模板更新事件（时间、操作者、变更摘要），支持审计与快速回滚，并仅保留最近 10 条记录；回滚入口固定展示在“设置”页面，并允许用户选择是否同时覆盖自定义 YAML 文本。  
- **FR-010**: 系统必须在保存前执行 dry-run 模拟加载，验证完整 YAML 可被 Clash 正常解析，并在失败时给出可操作的错误提示。  

### Key Entities *(include if feature involves data)*

- **SubscriptionSource**: 描述单个订阅站点链接、认证信息、刷新频率、最近状态。  
- **ProxyGroup**: 定义一组节点集合及其策略类型（select、url-test、fallback 等）。  
- **NodeMetric**: 记录节点测试结果（延迟、丢包、成功时间）及来源订阅。  
- **TemplateSnapshot**: 保存每次保存前后的 YAML 快照及元数据，支持回滚。  
- **FusionTestResult**: 汇总同地区节点的延迟测试结果、失败原因与时间戳，并仅保留最近 10 次测试，同时记录 dry-run 校验结果与错误原因。  

## Assumptions

- 假设所有节点和策略配置集中在单一模板文件中管理，不存在多模板并行场景。  
- 假设订阅站点提供标准化的 HTTP/HTTPS 链接，并可通过统一健康检查地址验证有效性。  
- 假设运维人员至少每日执行一次融合测试，系统保留最近 30 天的结果供比对。  

## Constraints & Tradeoffs

- 为兼顾易用性与灵活度，系统保留图形化编辑器作为默认入口，同时提供受权限控制的原始 YAML 编辑模式；仅授权运维或高阶用户使用，并记录日志以降低误操作风险。  

## 宪章符合性说明 *(mandatory)*

- **命令驱动架构**：新增 `subscription.update_links`、`template.save_snapshot` 等 Tauri 命令，前端通过 `src/services/subscriptionAPI.ts` 与新 Hooks (`useTemplateEditor`) 调用；补充 `src-tauri/tests/contract` 用例覆盖命令协议。  
- **敏感数据加密与最小持久化**：订阅链接、认证信息通过 `crypto_service` 加密存储，保存在现有命名空间，导出快照需脱敏或受密码保护。  
- **macOS 原生体验一致性**：编辑器 UI 复用 `src/components/UI` 的表单、标签与分栏组件；提供暗/亮模式预览，并在 `tests/ui` 覆盖核心流程。  
- **可恢复的自动化运营**：延迟测试与融合流程由 `src-tauri/src/services/subscription_service` 扩展，记录日志与状态；失败时回滚至最近成功快照。  
- **全链路测试准入**：新增 Vitest 单测覆盖表单状态管理，`tests/ui` 编写用户操作脚本，Rust 服务扩展 `cargo test` 覆盖链接替换与融合逻辑。  

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 95% 以上的订阅刷新操作在 5 秒内完成，并保持 YAML 结构差异仅限链接字段。  
- **SC-002**: 至少 80% 的新手用户在 10 分钟内通过图形界面完成一次节点增删并成功保存模板，满意度 ≥ 4/5。  
- **SC-003**: 多订阅融合测试的延迟结果刷新时间不超过 3 分钟，并提供最近三次测试的对比视图；测试成功率 ≥ 95%。  
- **SC-004**: 模板操作失败后 100% 自动回滚，并提示明确错误原因与下一步建议；操作日志覆盖率 100%，仅保留最近 10 次变更记录。  

## Clarifications

### Session 2025-10-18

- Q: 模板快照与操作日志需要保留多长时间？ → A: 仅保留最近 10 个快照/日志条目，超出后自动滚动覆盖。
- Q: 是否允许用户直接编辑原始 YAML？ → A: 保留图形编辑器，并提供受权限控制的原始 YAML 编辑入口。
- Q: 模板编辑 UI 应如何接入现有应用？ → A: 在 `SubscriptionManager` 内新增“模板编辑”页签，与订阅列表并列显示。
- Q: 如何处理模板中超出编辑器能力的自定义配置？ → A: 在 UI 提供文本框，保存时格式化验证；若仍无法通过则丢弃并提示未加载。
- Q: 过滤规则在可视化编辑中如何呈现？ → A: 提供正则文本与可视化助手并行维护。
- Q: 可视化编辑与外部 YAML 变更冲突如何处理？ → A: 阻止保存并提示重新加载最新模板。
- Q: 保存前需执行到何种校验级别？ → A: 执行 dry-run 模拟加载，确保 YAML 可被 Clash 解析。
- Q: 回滚入口应展示在何处？ → A: 在设置页面提供快照回滚入口。
- Q: 如何处理编辑器不支持的 YAML 片段？ → A: 保留为只读文本块并提示不会被编辑器修改。
- Q: 保存校验应采用什么顺序？ → A: 先执行 schema/引用校验，再进行 dry-run。
- Q: 检测到外部 YAML 更新时 UI 应如何响应？ → A: 自动刷新并提供“重新加载并覆盖 UI”或“放弃保存”选项。
- Q: 快照回滚时如何处理自定义文本？ → A: 自定义 YAML 独立保存，回滚时由用户决定是否套用。
- Q: 订阅链接剩余时间的提醒阈值是多少？ → A: 剩余 ≤ 5 分钟提示黄色警告，≤ 60 秒标红并暂存修改，需刷新链接后方可继续。
