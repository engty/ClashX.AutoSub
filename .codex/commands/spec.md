## Clarifications

### Session 2025-01-10

- Q: 目标用户群体和规模是什么？ → A: 个人用户（1-5个订阅站点，简单管理需求）
- Q: 技术选型优先级是什么？ → A: 平衡方案（Tauri 2 + React 18 + TypeScript + Rust，支持跨平台）
- Q: 数据迁移策略是什么？ → A: 无需迁移，设计符合Tauri技术栈的全新数据结构
- Q: 订阅站点认证机制复杂度如何？ → A: 中等复杂度认证（Cookie、Token、基础2FA），具备扩展到混合模式的前提条件
- Q: 系统部署和更新策略是什么？ → A: 应用内检查更新提示，用户主动触发更新，保证配置平滑迁移
- Q: 预定义订阅站点模板的更新机制是什么？ → A: 静态模板随应用升级更新，已生成配置不受影响，编辑时提示模板升级
- Q: 预定义模板的认证信息保护策略是什么？ → A: 模板保存在应用目录（订阅链接格式、Cookie模式、保存格式），用户凭据保存在~/.clash-autosub配置目录
- Q: 开发端调试功能的需求是什么？ → A: 独立的调试工具，与用户端应用完全隔离
- Q: 系统可观测性要求是什么？ → A: 最小化实现（仅关键错误日志）
- Q: 安全性实施标准是什么？ → A: 基础加密（敏感数据本地AES-256加密存储）
- Q: 错误处理策略是什么？ → A: 基础错误提示（显示错误信息，用户手动处理）
- Q: 网络依赖管理是什么？ → A: 基础网络处理（设置合理的超时时间，失败时记录错误）
- Q: 测试验收标准是什么？ → A: 增强测试覆盖（+用户界面测试 + 性能基准测试）
- Q: CLI依赖关系如何处理？ → A: 完全移除CLI相关要求，专注于纯UI架构

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 技术栈选型决策 (Priority: P1)

用户作为项目决策者，需要为 Clash AutoSub 从 CLI 应用转换为 macOS UI 应用选择合适的技术栈，确保性能、开发效率和用户体验的最佳平衡。

**Why this priority**: 技术选型是整个项目架构转换的基础，直接影响后续开发效率、性能表现和用户体验，必须首先确定。

**Independent Test**: 可以通过技术评估报告和原型验证来测试，提供不同技术方案的对比分析和性能测试结果。

**Acceptance Scenarios**:

1. **Given** 项目需要从 CLI 转换为 macOS UI 应用，**When** 完成技术调研，**Then** 输出包含 SwiftUI、Electron、Tauri 等方案的详细对比分析
2. **Given** 多个技术方案候选，**When** 评估完成，**Then** 确定最适合项目需求的技术栈并说明选择理由

---

### User Story 2 - UI界面设计 (Priority: P1)

用户作为 Clash AutoSub 的使用者，需要一个直观、现代化的 macOS 原生界面来管理 VPN 订阅，支持订阅站点管理、状态监控、配置更新等核心功能。

**Why this priority**: 用户界面是用户与系统交互的主要方式，直接影响用户体验和使用效率，参考 cc-switch 的简洁设计理念。

**Independent Test**: 可以通过界面原型和用户测试来验证，确保界面布局合理、交互直观、功能完整。

**Acceptance Scenarios**:

1. **Given** 用户打开应用，**When** 查看主界面，**Then** 显示订阅站点列表、状态信息和快速操作按钮
2. **Given** 用户需要管理订阅站点，**When** 点击相关操作，**Then** 能够添加、编辑、删除、测试订阅站点
3. **Given** 订阅状态发生变化，**When** 状态更新，**Then** 界面实时反映最新状态并提供视觉反馈

---

### User Story 3 - 系统集成体验 (Priority: P2)

用户作为 macOS 用户，希望应用能够与操作系统深度集成，支持菜单栏快速访问、系统通知、后台运行等功能，提供无缝的使用体验。

**Why this priority**: 系统集成是提升用户体验的关键因素，让应用更符合 macOS 用户的使用习惯。

**Independent Test**: 可以通过系统集成功能测试和用户体验测试来验证各项集成功能的可用性和稳定性。

**Acceptance Scenarios**:

1. **Given** 应用在后台运行，**When** 用户需要快速操作，**Then** 可以通过菜单栏图标访问主要功能
2. **Given** 订阅更新完成或失败，**When** 状态变化，**Then** 系统发送相应通知提醒用户
3. **Given** 系统启动，**When** 登录完成，**Then** 应用能够自动启动并恢复之前的状态

---

### Edge Cases

- 当用户网络连接不稳定时，应用如何处理订阅更新和状态同步？
- 当多个订阅站点同时需要更新时，如何处理并发请求和错误恢复？
- 当应用遇到权限问题（如文件访问、网络访问）时，如何引导用户解决？

### 错误处理策略
- **ERR-001**: 系统必须显示清晰的错误信息，包括错误类型和可能的原因说明
- **ERR-002**: 对于网络相关错误，必须显示网络状态检查建议
- **ERR-003**: 对于认证失败，必须提示用户检查凭据配置
- **ERR-004**: 对于文件权限错误，必须提供具体的权限设置指导
- **ERR-005**: 错误信息必须包含用户可操作的解决步骤或建议

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须实现纯UI架构的VPN订阅管理功能，无需CLI兼容性
- **FR-002**: 系统必须提供直观的订阅站点管理界面，支持增删改查操作
- **FR-003**: 系统必须实时显示订阅状态、更新时间和连接信息
- **FR-004**: 系统必须支持批量操作，如一键更新所有订阅
- **FR-005**: 系统必须提供配置导入导出功能，确保数据迁移安全，更新时保证配置平滑迁移
- **FR-006**: 系统必须支持 macOS 原生系统集成（菜单栏、通知、自动启动）
- **FR-007**: 系统必须提供清晰的错误提示和操作指导
- **FR-008**: 系统必须支持深色/浅色模式自动切换
- **FR-009**: 系统必须提供设置界面，允许用户自定义更新频率、通知偏好等
- **FR-010**: 系统必须设计符合Tauri技术栈的数据存储结构
- **FR-011**: 系统必须提供5-10个预定义订阅站点模板，包含订阅链接格式、Cookie模式和保存格式配置
- **FR-012**: 系统必须支持模板升级提示，允许用户确认是否升级到最新模板版本
- **FR-013**: 系统必须提供独立的开发者调试工具，用于测试和验证订阅站点模板配置

### Key Entities

- **订阅站点**: 包含名称、URL、认证信息（Cookie、Token、基础2FA）、状态、最后更新时间等属性（支持1-5个个人订阅站点，架构支持扩展到混合认证模式；支持预定义模板站点）
- **站点模板**: 包含订阅链接格式、Cookie获取模式、保存格式等配置信息，存储在应用目录内
- **用户凭据**: 用户名、密码、Token等敏感信息，独立存储在~/.clash-autosub配置目录
- **配置文件**: 包含应用设置、用户偏好、系统配置等信息
- **状态信息**: 包含连接状态、更新状态、错误信息等实时数据
- **通知消息**: 包含系统通知、错误提醒、成功提示等消息类型

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户能够在 3 次点击内完成订阅站点的添加和配置
- **SC-002**: 应用启动时间小于 3 秒，界面响应时间小于 500 毫秒
- **SC-003**: 95% 的用户能够在首次使用时成功完成至少一个订阅站点的配置
- **SC-004**: 系统通知准确率达到 98%，误报率低于 2%
- **SC-005**: 用户满意度评分达到 4.5/5.0 或以上
- **SC-006**: 应用内存占用低于 100MB，CPU 占用在空闲时低于 5%

### 测试验收要求
- **TEST-001**: 核心功能（订阅管理、状态监控、配置导入导出）必须有单元测试覆盖，覆盖率不低于80%
- **TEST-002**: 主要用户界面必须包含自动化UI测试，确保交互流程正常工作
- **TEST-003**: 系统必须通过性能基准测试，验证启动时间、响应时间和资源占用符合标准
- **TEST-004**: 必须包含基本的集成测试，验证Tauri前后端通信和系统集成功能正常
- **TEST-005**: 安全相关功能（数据加密、凭据存储）必须通过专项安全测试验证

## 非功能性质量属性

### 可观测性要求
- **LOG-001**: 系统仅记录关键错误日志，包括订阅更新失败、网络连接错误、认证失败等关键异常
- **LOG-002**: 日志文件存储在用户配置目录，支持最多30天的滚动保留
- **LOG-003**: 错误日志必须包含足够的上下文信息用于问题诊断，但不包含敏感用户数据

### 安全性要求
- **SEC-001**: 敏感用户数据（用户名、密码、Token、Cookie等）必须使用AES-256算法本地加密存储
- **SEC-002**: 加密密钥必须基于用户设备特定信息生成，不支持跨设备同步
- **SEC-003**: 系统配置文件和订阅链接数据可以明文存储，但用户认证信息必须加密
- **SEC-004**: 内存中的敏感数据在处理完成后必须及时清除，避免长期驻留

### 网络依赖管理
- **NET-001**: 所有网络请求必须设置合理的超时时间（订阅更新30秒，连通性测试10秒）
- **NET-002**: 网络请求失败时必须记录详细错误信息到错误日志
- **NET-003**: 系统必须能够检测网络连接状态，在无网络时提供适当提示
- **NET-004**: 订阅站点更新失败时不影响其他站点的正常更新操作

## macOS UI 应用要求
- **UI-001**: UI 应用必须遵循 macOS Human Interface Guidelines
- **UI-002**: UI 应用启动时间必须 < 3秒
- **UI-003**: UI 应用响应时间必须 < 500ms
- **UI-004**: UI 应用必须支持系统集成（菜单栏、通知等）

### 数据一致性要求
- **DATA-001**: 数据存储必须支持Tauri的跨平台特性
- **DATA-002**: 加密算法必须在Tauri框架内安全实现
- **DATA-003**: 配置数据必须支持导入导出备份功能

## 技术选型分析

### 候选技术栈对比

基于 cc-switch 项目的成功经验和 Clash AutoSub 的具体需求，分析以下技术栈选项：

1. **SwiftUI + Combine (原生推荐)**
   - 优势：原生性能、完美系统集成、Apple 生态支持
   - 劣势：学习成本、仅支持 macOS 平台

2. **Electron + React/Vue**
   - 优势：跨平台、Web 技术栈、开发效率高
   - 劣势：资源占用大、性能相对较低

3. **Tauri 2 + React 18 + TypeScript + Rust (已选定方案)**
   - 优势：轻量级、高性能、跨平台、现代化架构
   - 劣势：生态相对较新、学习成本中等
   - 技术栈：Tauri 2 (updater/process/opener/log/tray-icon) + React 18 + TypeScript + Vite + Rust

### UI/UX 设计原则

参考 cc-switch 的设计理念：

1. **简洁直观**：界面布局清晰，功能一目了然
2. **一致性**：遵循 macOS 设计规范，保持视觉和交互一致性
3. **响应性**：提供即时反馈，状态变化实时可见
4. **可访问性**：支持键盘导航、屏幕阅读器等辅助功能
